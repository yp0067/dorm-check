# 归寝网页部署说明

这是你自己部署的 GitHub Pages 版本，不依赖之前打不开的 `chatgpt.site`。GitHub 放页面，Supabase 保存大家提交的同一份记录。

## 一、先准备 GitHub 仓库

1. 登录 GitHub，新建一个仓库，例如 `dorm-check`。记下自己的 GitHub 用户名。
2. 先保留空仓库，后面再上传网页文件。
3. 最终网页地址通常是 `https://你的GitHub用户名.github.io/dorm-check/`。

名字和寝室名单包含在源码里。若你使用公开仓库，别人能看到这些名单。姓名入口也不能验证本人，知道名字的人能选择对应身份。

## 二、建立 Supabase 数据库

1. 打开 https://supabase.com/dashboard ，注册并新建一个项目。数据库密码由你自己保存，不用放进网页配置。
2. 等项目准备完成，进入 **SQL Editor**，新建查询。
3. 打开部署包中的 `后台/初始化数据库.sql`（源码中对应 `supabase/migrations/202610260001_dorm.sql`），复制全部内容到 SQL Editor，点击 **Run**。
4. 确认没有报错。此脚本创建 `dorm_nights`、`dorm_sessions` 两张表及保存函数；不包含学生的示例请假数据。

## 三、把后台功能放到 Supabase

1. 在左侧进入 **Edge Functions** → **Deploy a new function** → **Via Editor**。
2. 将函数名称设成 **night**。
3. 打开部署包的 `后台/粘贴到云函数.js`，复制全部内容，替换编辑器中的默认示例代码。保留编辑器默认入口文件名即可，代码无外部依赖。
4. 发布函数。找到该函数的 **Verify JWT** / **Enforce JWT Verification** 设置，将它关闭并保存。这里只关闭平台预检查；实际读写仍由代码里的会话和角色规则检查。
5. 在 **Edge Functions → Secrets** 新增一项：

   - 名称：`ALLOWED_ORIGIN`
   - 值：`https://你的GitHub用户名.github.io`

   这里**不带仓库名称，不带最后的斜杠**。例如网页地址是 `https://xiaohu.github.io/dorm-check/`，这里只填 `https://xiaohu.github.io`。如果以后使用自己的域名，把值改成那个网址的协议和域名。

6. 保存后如控制台提示需要更新函数，重新部署。`SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY` 使用云函数自动提供的服务端环境变量；不要把 service_role 或任何 secret key 复制到 GitHub。
7. 复制函数地址，格式是 `https://你的项目编号.supabase.co/functions/v1/night`。
8. 进入 **Settings → API Keys**，复制 **Publishable key**（通常以 `sb_publishable_` 开头）。旧项目的 `anon` 公开密钥也可以使用。**不要复制 Secret key 或 service_role。**

## 四、填写网页配置并上传 GitHub

1. 解压“部署包”，找到 `网页文件/config.json`，用记事本打开，将两项空字符串替换成自己的信息：

```json
{
  "apiUrl": "https://你的项目编号.supabase.co/functions/v1/night",
  "publicKey": "这里粘贴 Publishable key"
}
```

2. 保存。保留英文双引号和逗号。
3. 打开 GitHub 仓库，点 **Add file → Upload files**。上传“网页文件”**里面的全部文件和 assets 文件夹**，不要上传外层“网页文件”文件夹，也不要上传整个压缩包。
4. 上传完成后，仓库根目录应该直接看见 `index.html`、`config.json`、`favicon.svg` 和 `assets/`。
5. 进入 **Settings → Pages**：
   - Source 选择 **Deploy from a branch**。
   - Branch 选择 `main`，目录选择 `/ (root)`，保存。
6. 等待 GitHub 显示已发布的网址。打开网址，看到姓名输入框后输入自己的姓名。

这条直接上传网页的路径不需要安装 Node，也不需要 GitHub Actions。

## 五、正式发给全班前，做一次互相读取检查

建议选一个单独的测试日期，例如昨天，避免把示例算进今晚统计。

1. 一台设备输入一位同学的姓名，切换到测试日期，填写一次请假并提交。
2. 另一台设备输入“王诗琪”，切换到同一日期，确认能看见刚才的请假；勾选时间、原因，在备注中写“测试”，提交。
3. 用对应寝室长的姓名进入，逐人选择在寝或未归，包括寝室长本人，提交。
4. 输入“胡运萍”，同样选择测试日期，确认三列都能看见刚才的信息，并能生成上报文字。
5. 刷新网页后记录仍存在；切回今天，不应继承测试日期的查寝结果。
6. 在 Table Editor 中只删除这一天的测试记录（`dorm_nights` 对应日期的一行），不要清空整张表。

## 常见提示

| 提示或现象 | 检查位置 |
| --- | --- |
| 尚未连接共享数据库 | `config.json` 的两项是否都已填写并上传 |
| 页面空白或 assets 404 | `index.html` 是否在仓库根目录，assets 是否完整上传 |
| 无法连接共享数据库 | 函数地址是否正确、函数是否已发布、ALLOWED_ORIGIN 是否与网页域名完全一致；也检查手机网络是否能访问 Supabase |
| 401 / Invalid JWT | 云函数 `night` 的 Verify JWT 是否已关闭，配置是否用了 Publishable key |
| 后台尚未配置允许访问的网址 | Edge Functions Secrets 中补上 `ALLOWED_ORIGIN` |
| 共享数据库暂时无法读写 | SQL 是否成功执行；查看函数日志与两张表是否存在 |
| 有新记录提交，请先刷新 | 有人刚刚提交了更新。先记下未保存内容，刷新后重填；系统不会覆盖别人刚提交的记录 |

## 如果选择上传完整源码

完整源码包是另一条部署路径：修改 `public/config.json`，上传源码根目录全部文件（包括 `.github/`），Pages 的 Source 改选 **GitHub Actions**。随附工作流会自动安装、测试、构建和发布。

不要把这条源码部署方法和前面的“直接上传网页文件”混着设置。初次使用建议直接上传网页文件。

本地验证已覆盖主要规则和网页操作；尚未接入你的真实云账号。GitHub Pages 和 Supabase 能否在你们的校园网络、微信内浏览器正常访问，需要上线后实际确认。
